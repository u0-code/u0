# 首次运行

## 设置 u0 {#set-up-u0}

新的主目录会先打开 **设置 u0**，每一步都是可选的：

- **智能体**：u0 起初带有的智能体，每个都可以在它那一行启用或停用、安装或登录；
  **取消** 停止正在安装的那个。**浏览 ACP 注册表** 打开 **设置 › 智能体**。
- **你的其他设备**：**显示配对链接** 为另一台 Mac 或手机应用显示一个链接及其二维码
  （见[远程控制](remote.md)）。
- **项目与历史记录**：拖入一个文件夹把它添加为项目，或勾选你的智能体曾经工作过的文件夹。

**继续** 添加勾选的文件夹，询问遥测（见下文），之后不再显示这一设置。还没有项目时，
窗口接着问 **我们要做什么？**：打开文件夹、克隆仓库、新建空项目，或
**不指定项目直接开始 (⌥⌘N)**。

## 遥测 {#telemetry}

u0 第一次打开时（若显示设置页，则在你从设置页继续之后），**欢迎使用 u0** 会问它可以向开发者透露多少信息。拖动滑块：滑块下方
就是该级别会发送的确切 JSON，由 u0 在这台 Mac 上生成，而不是示例。选择 **以该级别继续**，
或选择 **保持关闭遥测**，即级别 0。之后可在 **设置 › 遥测**
中更改；在任何级别下，**显示发送的内容** 都会显示次日那批数据的确切 JSON。
**重置安装 ID** 让今后的数据以一个新的随机 ID 发送，与旧 ID 不再关联。

共有四个级别，与 KDE 类似。每一级都发送前一级的全部内容，并多一些：

| 级别 | 发送的内容 |
|---|---|
| **0，关闭** | 只在第一次启动时发送一次，此后再也不发（更新后也不发）：u0 的版本、提交和渠道（stable 或 nightly）、系统（`macos 26` 或 `linux`）以及处理器（`aarch64` 或 `x86_64`）。没有 ID。 |
| **1，基础** | 每天一次：以上内容、本次安装的一个随机 ID、已启用的智能体（它们的注册表 ID 和版本）、这台 Mac 已配对的 Mac 数量，以及是否允许别人控制这台 Mac。 |
| **2，用量** | 另外还有当天的计数：按智能体统计的线程数、轮数、创建的工作树数、计划任务的轮数和工作流运行次数、调用 u0 工具的次数（按工具名）、打开窗口各页面的次数（按名称）、崩溃次数。 |
| **3，详细** | 另外还有：从启动到第一帧的时间、u0 及其运行的程序占用的内存、错误的种类（按种类，例如某个智能体没能启动）、选择的模型（按 ID）、窗口的大小和缩放、外观（浅色、深色、跟随系统）以及系统语言。 |

任何级别都不会发送你或智能体写的内容、路径、项目、仓库、分支或线程的名称、主机名、地址、
电子邮件、令牌或错误的文字。所发送的名称（智能体的 ID、工具的、页面的、模型的）必须是简短的标记；
其他内容一律丢弃。

在你选择级别之前，级别 0 以上的内容都不会发送。当天的计数保存在 `<home>/telemetry.json` 中，
重启也不会丢失；发送失败的一批数据会被丢弃。手动构建（渠道 `dev`）从不发送任何内容。

数据发往一个 Cloudflare Worker（其源代码在仓库的 `telemetry/` 文件夹中），它按 schema
检查每批数据，拒绝任何不符合的内容，并保存这批数据及其来源国家，而不是地址。

在没有窗口的服务器上，在它的 `settings.json` 中设置 `"telemetry": 0` 到 `3`。
组织可以用[策略](reference/policy.md)设定或锁定级别。

## 你的智能体 {#your-agents}

u0 启动时默认启用三个智能体：**Claude Code**（`claude-acp`）、**Codex**
（`codex-acp`）和 **Antigravity**（`antigravity-acp`）。
[ACP 注册表](https://agentclientprotocol.com)列出的其他所有智能体（Gemini CLI、
GitHub Copilot、OpenCode 等）都可以在 **设置 › 智能体** 中启用。

需要处理的智能体显示在侧边栏底部，带有它的徽标和它需要什么：**登录**、**安装**、
**安装中** 或 **已停止**。几个智能体合为一个，徽标叠在一起（它们需要的不同时显示个数，
例如 **3 个智能体**），点开是 **设置 › 智能体**。

### 安装 {#installing}

u0 按注册表所说的方式安装智能体：

- **二进制**发布版会被下载并解压到 `<home>/agents/`；
- **npm** 包用 `npm` 安装（以 `npx` 运行的智能体），**Python** 包用 `uv` 安装
  （以 `uvx` 运行的智能体），都安装到 u0 的主目录中。这些需要你的 `PATH` 上有 `npm` 或 `uv`。

安装的内容按原样运行。当某个智能体缺失，或旧版本启动失败时，u0 会安装注册表中的最新版本。
它每小时重新读取一次注册表（`check_agents`），并每五分钟重试已停止的智能体。

**设置 › 智能体 › 重新读取注册表** 会立即读取。智能体的页面上有 **卸载**。

### 登录 {#signing-in}

登录由智能体自己完成；u0 从不接触凭据。

- **Claude Code** 和 **Codex** 会运行你 `PATH` 上已有的 `claude` 和 `codex`
  （通过 `CLAUDE_CODE_EXECUTABLE` 和 `CODEX_PATH`），因此使用与你终端中相同的版本、
  登录和设置。没有的话，适配器会运行它自带的版本。
- 通过 ACP 登录的智能体（Antigravity，使用你的 Google 账户）会显示它的登录方式；
  登录后线程即会打开。
- 否则，**登录** 会在“终端”中运行智能体自己的程序（在你控制的另一台 Mac 上，则在那里的某个
  u0 终端中），**我已登录** 会再检查一次。

智能体支持的话，它的页面上有 **退出登录**。

### 智能体的页面 {#an-agents-page}

每个已开启的智能体都列在设置列表的 **智能体** 之下；在那里打开它，或在 **设置 › 智能体**
中按它的名字。它的页面会说明它的状态（**就绪**、**运行中**、**需要登录**、**未安装**、
**安装中**、**已停止** 或 **关闭**）、注册表给出的适配器及其版本，以及它驱动的你自己的 CLI。
名字下方是此刻能做的事：**新线程**、**安装**、**更新到** 新版本、**登录**、**退出登录**、
**开启** 或 **关闭**，以及 **卸载**。再往下：

- **实例**：**添加实例** 会以独立的登录和设置再运行一次该智能体，与第一个并存。
  Claude Code 和 Codex 支持这一点：新实例的 `CLAUDE_CONFIG_DIR` 或 `CODEX_HOME`
  指向 `<home>/accounts/` 下它自己的文件夹。在某个实例中开始的线程会一直属于该实例。
  移除一个实例会把它停用并忘记它的变量；它的文件夹（连同登录信息）会保留。
- **变量**：在智能体启动时设置到它的环境中。把某个变量标为 **机密**，它就会保存在 macOS
  钥匙串中，绝不写入 u0 的文件。值可以是 1Password 引用（`op://vault/item/field`），
  在智能体启动时用 `op` 读取。每个变量都标明来源：**钥匙串** 或 **1Password**。
  管理员策略锁定的设置会说明由谁管理，在这里不能更改。
- **u0 的工具**：它的新线程是否获得 [u0 的工具](tools-for-agents.md)。
- **使用此命令**：你自己的一条命令行，用它代替注册表的方式来启动智能体（你自己的构建、
  版本管理器提供的版本）。它必须在标准输入和输出上支持 ACP；**检查它是否支持 ACP**
  会保存并试一下。
- **你自己的模型**：在输入框中与智能体列出的模型一起提供的模型 ID。智能体可能会拒绝它不认识的模型。

## 你的第一个线程 {#your-first-thread}

1. 添加一个项目：从“访达”把文件夹拖到侧边栏上，或按 **添加项目**
   （见[项目与线程](projects-and-threads.md)）。
2. 按 ⌘N。在输入框的模型标签上（或按 ⇧⌘M）选择智能体及其模型，写下任务，然后按 Return。
3. 在对话区中跟进。智能体在行动前询问时，在它的卡片上作答。

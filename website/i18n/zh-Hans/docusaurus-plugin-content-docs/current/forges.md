# 拉取请求与议题

侧边栏底部的 **拉取请求** 和 **议题** 列出你各个项目在其代码托管处的拉取请求和议题。

## 托管平台 {#hosts}

**设置 › 源代码管理 › 托管平台** 显示每个托管平台以及 u0 访问它的方式。你在这里填写的令牌会代替 CLI 自己的登录，并保存在 macOS 钥匙串中，从不写入文件。它也可以是 1Password 引用（`op://vault/item/field`），使用时通过 `op` 读取。

| 托管平台 | u0 如何访问 | 令牌 |
|---|---|---|
| GitHub | `gh` CLI | 你通过 `gh auth login` 得到的，或在这里填写的 |
| GitLab（名字中含有 `gitlab` 的任何主机） | 其 REST API；用 `glab` 打开合并请求 | 在这里填写（也会传给 `glab`） |
| Bitbucket（`bitbucket.org`） | 其 REST API | 在这里填写（令牌，或 `user:app-password`） |
| Azure DevOps（`dev.azure.com`、`*.visualstudio.com`） | 其 REST API | 在这里填写（个人访问令牌） |
| Linear | 其 API | 在这里填写（API 密钥） |

项目的托管平台从其 `origin` 读取。没有令牌时，会不带令牌请求 API，只能访问公开内容。

对于议题，项目可以在其项目设置中改为绑定一个 **Linear 团队**（用它的键，如 `ENG`）；Bitbucket 和 Azure DevOps 项目要使用议题必须这样做。

## 页面 {#the-pages}

每个页面打开时显示屏幕上那个线程所在的项目（在由多个仓库组成的项目里，是该线程工作的那个仓库），列出该项目的条目，或 **所有项目** 的条目合在一起。由多个仓库组成的项目按仓库逐个列出（`项目 / alpha`）。不在任何代码托管平台上的项目不会列入 **所有项目**，并会有一条通知写明它和原因。顶栏写明列出的是哪些仓库，以及上次读取的时间。

列表上方是搜索框和筛选：

- **状态**：打开、已关闭、已合并（拉取请求）、全部；
- **仓库**：**所有项目**，或其中一个；
- **作者**（拉取请求）：**任何人** 或 **你**；**负责人**（议题）：**任何人** 或 **我**；
- **标签**（拉取请求）：列出条目中的某个标签；
- **跟踪器**（议题）：项目的托管平台，或 **Linear 团队…**，它会请你输入团队的键，并把项目绑定到该团队。

旁边的菜单决定列表的顺序（**排序：最近更新**、**排序：最早优先**，拉取请求还有 **排序：改动最多**，议题还有 **排序：优先级**），可以显示你保存的视图，并用 **保存此视图** 保留当前筛选（设置中的 `views`）；**移除** 会删掉一个已存视图。**重新读取** 会重新列出。

拉取请求分组列出：**等你审查**（打开且请你审查）、**你的**（由你打开，以 `gh` 登录的账号为准）和 **关注中**（其余的）。每一行显示状态、标题、编号和标签；仓库、作者、分支和最近更新时间；以及审查情况、检查、评论数和增删的行数。议题按项目列出，每一行显示优先级（Linear 的）、键、状态、标题、标签、关于它的线程以及最新一个线程的状态。拉取请求在单独的页面中打开；议题在列表旁打开。

在列表旁读到的议题会显示它的状态、键和托管平台（Linear 议题还有团队），以及 **在 GitHub 中打开**（或其所在平台）和 **关闭议题** / **重新打开议题**；它的标题、标签、状态、优先级、负责人和描述；关于它的线程（点按即可打开），以及 **开始线程** 和 **分拣它**；还有它的评论，以及一个 **发表评论** 的输入框，用 **评论** 或 ⌘↵ 发送。按 Esc 收起。

条目的菜单：

- 拉取请求：**压缩并合并**、**合并**、**变基并合并**、**检查通过后合并**（都会删除分支）；**准备好审查** / **转为草稿**；**就此开一个线程，在工作树中** 或 **就此开一个线程，在此处检出**；**复制检出命令**；**载入新提交**；
- 议题：**开一个关于它的线程**，以及 **分拣它**（开一个线程来分拣它）；
- 两者都有：**关闭** / **重新打开**、**编辑标题和描述**、**在托管平台上打开**、**复制链接**。

在条目的视图中，你可以添加标签、审查者和指派人，重新运行失败的检查（**再次运行**）并查看其 **日志**，还可以从仓库的议题模板新建 **新议题**（GitHub）。

描述或评论中的图片（Markdown 图片，或 `<img>` 标签，只读取其地址）显示在写下它们的位置。项目所在的服务器逐一获取，只通过 HTTPS，且只从公共互联网获取：每个条目最多 50 张，每张最大 8 MiB、每边最多 8192 像素，动图最多 300 帧。一分钟内再次请求的图片直接显示已获取的内容。GitHub 上附加的文件（`github.com/user-attachments/…`）会带上你的 GitHub 令牌请求，因此私有仓库的图片也能显示；其他地址都不会收到该令牌。

## 审查拉取请求 {#reviewing-a-pull-request}

拉取请求会在单独的页面中打开，包含 **概要**、**时间线**、**代码**、**讨论** 和 **导读**：

- **代码** 把文件分为代码、测试、模拟、生成文件和文档。边看边在文件上勾选 **已查看**；文件再有改动时会重新显示为未查看。
- **评论此行** 把一条评论排进你的下一次审查。最后用 **评论**、**批准** 或 **请求修改** 完成审查。
- **讨论** 有 **回复** 和 **解决** / **重新打开**；已解决的和机器人的讨论会被折叠。
- **导读** 让写作者写一份审查导读，帮你按它阅读这次改动。如果导读写完后又有新提交，它会注明。

## 各托管平台支持什么 {#what-each-host-supports}

| | GitHub | GitLab | Bitbucket | Azure DevOps | Linear |
|---|---|---|---|---|---|
| 拉取请求 | 以上全部 | 合并、关闭、重新打开、草稿/就绪、评论、批准、编辑、回复、解决、标签 | 合并、拒绝、评论、批准、请求修改、编辑、回复、解决 | 合并、放弃、重新打开、草稿/就绪、评论、编辑、回复、解决 | — |
| 议题 | 支持 | 支持 | 通过 Linear | 通过 Linear | 列出、读取、评论、编辑、关闭、重新打开、创建 |
| 审查者、指派人、检查日志、重新运行 | 支持 | 在 GitLab 自己的页面上 | — | — | — |

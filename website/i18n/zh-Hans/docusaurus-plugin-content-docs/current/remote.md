# 远程控制

一台机器上的 u0 可以从别处的 Mac 使用：它的智能体、线程、文件、git
和终端，就像你坐在它面前一样。每个 u0 都能担任两种角色：

- **被控制**：允许其他设备控制这台 Mac（或运行 `u0-server` 的 Linux 机器）；
- **控制**：在这个窗口中，把其他 Mac 与本机并列掌控。

两者都在 **设置 › 设备** 中，且默认都是关闭的。

## 设备如何接入 {#how-a-device-comes-in}

设备凭密钥接入，从不凭密码：

1. 配对时，控制方 Mac 会为那一台机器生成一把 Ed25519 密钥。私钥留在它的钥匙串中，只发送公钥。该机器以其 `SHA256:` 指纹列出它。
2. 配对需要一个配对码：128 位随机数，只能使用一次，十分钟内有效，只保存在内存中（重启即失效）。
3. 此后桌面端每次建立连接时，该机器都会发送一个新的随机数（nonce），桌面端用它的密钥对其签名。没有任何秘密经过网络传输，也没有任何秘密存放在该机器上。

设备发出的每个调用，都在被控制的这台机器上，按该设备可以做什么进行检查。只读的设备只能查看线程、差异以及你的项目和其工作树中的文件，不做任何更改；它请求的其他任何事都会被拒绝。

关闭监听会立即切断所有连接，并作废所有未使用的配对码。对某台设备点击 **撤销** 会删除它的密钥并关闭它的连接，访问到期时也一样。

## 允许其他设备控制这台 Mac {#let-other-devices-control-this-mac}

在 **设置 › 设备** 中，打开 **允许其他设备控制这台 Mac**。（u0 菜单中的
**显示配对码…** 效果相同，并会打开该页面。）

此后 u0 只在 `127.0.0.1` 上监听，端口为 4317（即
`<home>/devices.json` 中的 `port`；同一台机器上的第二个 u0 请另设一个）。
网络上的任何东西都无法直接访问这个端口。设备可以通过以下两种方式之一访问它：

- **cloudflared 隧道。** 在 **访问方式 › 隧道（cloudflared）** 下，点击
  **启动**。u0 会运行你 `PATH` 中的 `cloudflared`（用
  `brew install cloudflared` 安装）。默认是快速隧道：每次启动都会得到一个新的
  `trycloudflare.com` 地址，因此设备必须用新链接重新配对。若要保持同一个地址，请使用你自己的命名隧道：
  输入它的主机名和隧道令牌，然后点击 **使用**。**使用快速隧道** 可切换回去。
- **SSH 端口转发**，在控制方 Mac 上执行：
  `ssh -L 4317:127.0.0.1:4317 host`，然后用 `127.0.0.1` 链接配对。
- **网络。** 在 **访问方式 › 监听于** 下，除 **这台 Mac** 外选择 **Tailscale** 或 **所有网络**（包括 Tailscale）。此后 u0 还会在该网络的地址上、在其自身端口的下一个端口（默认 4318）监听，并在那里自己使用 TLS，证书由它自己生成并保存在钥匙串中。访问方式中会列出访问它的每个地址。

在设备被允许进入之前，u0 同时最多保留 64 个等待中的连接，每个只保留几秒；浏览器中的网页会被直接拒绝。能访问到隧道的任何人仍可以占满这些连接，从而让设备一时无法进入：隧道的地址并不是秘密。

**提供服务时保持 Mac 唤醒** 让这台 Mac 在无人值守时也能被访问（u0
在监听期间运行 `caffeinate`）。

### 配对链接 {#the-pairing-link}

在 **将设备与这台 Mac 配对** 下，u0 会显示一个配对链接及其二维码：

```
u0://pair?host=<host>#<code>
```

host 是在 **通过何种方式访问** 下所选的方式：**最佳**（隧道开启时用隧道，其次是 Tailscale、局域网，最后是 `127.0.0.1:<port>`），或其中之一。网络上的链接还带有 `pin=`，即这台 Mac 证书的 SHA-256，使设备在那里只信任这台 Mac。该链接只能使用一次，十分钟内有效。

在链接上方选择下一个链接允许什么；每次选择都会立即生成一个新链接：

- **它可以做什么**：**全部**，或 **只读**。
- **多长时间**：**直到撤销**、**一天**、**一周** 或 **30 天**。到期后设备会被拒绝，需要用新链接重新配对。
- **让它进入前先问我**：设备完成配对后，会在 **控制这台 Mac 的设备** 下等待，直到你允许它进入。适用于你发给别人的链接。
- **双向配对**（仅限 **全部**）：如果来配对的 Mac 提出请求，这台 Mac 会反向与它配对，并在这里控制它。用于你自己的 Mac；默认关闭。**复制** 会复制它，**新链接** 会生成另一个。在另一台 Mac 上打开它、扫描它的二维码，或将它粘贴到那里。

### 控制这台 Mac 的设备 {#devices-that-control-this-mac}

每台已配对的设备都会列出它提供的名称、它可以做什么及到何时为止、其密钥的指纹、配对时间以及最近一次连接的时间。**撤销** 会立即切断它。

等待中的设备会显示 **允许进入** 和 **拒绝**。允许它进入之前，请确认它的指纹与设备上显示的一致。

## 控制其他 Mac {#control-other-macs}

打开 **控制其他 Mac**。然后在 **与另一台 Mac 配对** 下，粘贴另一台机器的配对链接并点击 **配对**。打开一个
`u0://pair` 链接（从浏览器、扫描二维码或 `open`）效果相同。
u0 菜单中的 **配对设备…** 会打开控制功能并带你到那里。

u0 在配对前会询问你：它会给出主机名以及为该主机生成的密钥的指纹。

### 双向同时配对 {#both-ways-at-once}

确认框中有 **同时允许它控制这台 Mac**。勾选后，这台 Mac
开始监听，对方则凭这台 Mac 生成的一次性配对码，用它自己的密钥反向配对。如果对方本身是通过
`127.0.0.1` 被访问的，它就在 `127.0.0.1` 访问这台 Mac，否则只能通过这台 Mac 自己的隧道访问，而该隧道必须已开启。对方无法访问这台 Mac 时，配对保持单向，并说明原因。只有链接是以 **双向配对** 生成的，对方才会反向配对；名称与这台 Mac 已在别处配对的机器相同的机器会被拒绝，绝不会取而代之。（当这台 Mac 的窗口运行在 launchd 服务上时，不提供该复选框。）

### 一个窗口中的多台 Mac {#several-macs-in-one-window}

打开控制功能后，你配对过的每台机器都会与这台 Mac 一起出现在窗口中：

- 侧边栏为每台机器显示一行（这台 Mac 排在最前），其下是它的项目和线程，以及它是否可访问。
- 新线程、⌘K 和 ⌘P 会标明每个项目所在的机器。
- 设置对话框顶部有一个机器选择器。某台机器的智能体、项目、任务、共享设置以及它保存的内容，都从该机器读取并保存在该机器上。外观和按键仍属于这台 Mac。
- 需要终端的智能体登录，会在该机器上的 u0 终端中进行。

**这台 Mac 控制的 Mac** 会列出它们，以及你的密钥指纹、各自运行的版本和状态：在此窗口中、正在连接、离线或被拒绝。**重新连接** 会立即重试；**忘记** 会移除该机器，并从钥匙串中删除它的密钥。

### 另一台 Mac 上的开发服务器 {#a-dev-server-on-another-mac}

另一台 Mac 上终端运行的开发服务器可以在这里打开：**打开**（在侧栏的服务器中、抽屉的打开预览中，或 ⌘ 点按其地址）会通过一个独立的连接把它的端口带到这台 Mac，以与窗口相同的方式签名登录，然后在你的浏览器中以这台 Mac 上 `127.0.0.1` 的某个端口打开。只有在那里可以做全部事情的 Mac 才能打开。

### 连接断开时 {#when-a-link-drops}

断开的机器会显示为离线，窗口中已有的内容仍可阅读，并会自动重新连接（先等待 1 秒，之后逐渐延长，两次尝试之间最长 30 秒）。它的服务器会保留最近发出的 16 MiB 内容；回到该服务器同一次运行的窗口，会按顺序收到它错过的一切。它的服务器重启后，或错过的内容更多时，窗口会重新读取全部内容。离线期间你所做的操作会在连接恢复后发送。拒绝了这台 Mac 的机器不会被重试，直到你点击 **重新连接**。

## Linux 服务器 {#a-linux-server}

`u0-server`（见[安装](install.md#on-linux-u0-server)）启动时即开始监听，如果之前开启了隧道则启动隧道；在终端中运行时，它会打印：

```
u0 serves on ws://127.0.0.1:4317
Pair a desk with it, once, in the next ten minutes: u0://pair?host=…
```

随后是该链接的二维码。在输出写入日志的地方运行时（如作为服务），它只说明在哪里提供服务，不打印链接：请改为在那台 Mac 的窗口中为桌面端配对。通过隧道或 `ssh -L` 访问它，然后按上文所述从 Mac 配对。

## 文件 {#files}

| 文件 | 位置 | 内容 |
|---|---|---|
| `devices.json` | 在被控制的机器上 | 允许接入的设备（`label`、`key`（形如 `ssh-ed25519 AAAA…`）、`scope`：`full` 或 `read`、`until`：访问到期时间、`waiting`：直到你允许它进入、`paired`、`seen`）、`port`，以及是否监听（`serve`）、在哪些网络上监听（`bind`）、是否运行隧道（`tunnel`）、是否保持唤醒（`awake`），和命名隧道（`named`：`{token, host}`）。 |
| `servers.json` | 在控制方 Mac 上 | 已配对的机器（`name`、`host`、`key`：为其生成的密钥的公钥、`pin`：通过网络访问的机器的证书），以及 `control`。每把私钥都保存在钥匙串中的 `server/<fingerprint>` 下。 |

两者都拒绝未知字段。无法读取的文件会保持原样，在修复或移走之前，没有设备能够接入（`devices.json`），也没有机器能被访问（`servers.json`）；移走后请重新配对。

:::caution

命名隧道的令牌以明文形式存储在 `devices.json` 中。

:::

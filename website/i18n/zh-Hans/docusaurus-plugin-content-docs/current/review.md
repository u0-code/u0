# 审查、提交与拉取请求

右侧栏显示一个线程做出的成果。⌥⌘B 显示或隐藏它，⇧⌘B 将它展宽盖过对话，⌘D 打开审查。

## 标签页 {#tabs}

右侧栏一开始有 **差异** 和 **详情**。**+**（⌘T）打开其他标签页；菜单打开时，按一个字母即可选择：

| 字母 | 标签页 |
|---|---|
| T | 终端 |
| B | 预览 |
| F | 文件 |
| D | 差异 |
| P | 拉取请求（有了拉取请求后标题为 `#N`） |
| S | 旁聊 |
| V | 设备（见[模拟器](simulators.md)） |
| I | 详情 |

文件会作为单独的标签页打开。⌘W（或中键点击）关闭标签页，⇧⌘T 重新打开最近关闭的一个。

## 差异 {#diff}

选择要比较的内容：

- **第 *n* 轮**：最近一轮改了什么；
- **全部**：线程改动的全部内容（还没有轮次时为 **未提交**）；
- **分支**：从分支离开其基点处（默认为 main；**against** 标签可选择其他分支）到当前文件，包括未提交的改动；
- 一个提交，从 **提交** 中选择；
- **编辑**：一次工具调用的改动。

工具栏有文件树、**展开所有文件** / **折叠所有文件**、**并排**（或上下排列）、**长行换行**、**忽略仅空白的改动**、**隐藏测试文件**、**在差异中查找** 和 **重新读取改动**。在包含多个仓库的文件夹中，用一个标签选择仓库。

### 给智能体的评论 {#comments-for-the-agent}

在某一行上按 **+** 即可评论它。你的评论显示在对应行的下方（每条都有 **撤回**），**把 *n* 条评论放进给 *智能体* 的输入行** 会把它们以 `- path:line — comment` 的形式放进输入框，由你发送。

### 提交与推送 {#commit-and-push}

每个文件都有一个复选框：取消勾选的文件不会进入下一次提交。差异下方有：

- **提交…** 打开提交表单。**撰写** 让写作者起草提交信息（附带你在 **设置 › 写作** 中的说明）。**提交** 暂存全部文件（取消勾选的除外）并以你的身份提交；没有提交信息时，使用线程标题。**提交并推送** 还会推送（`git push -u origin HEAD`）。
- **创建 PR** 让写作者撰写标题和描述，然后提交、推送并打开拉取请求。在默认分支上时，它会先创建一个独立分支（`<prefix><name>`）。GitHub 的拉取请求用 `gh pr create` 打开，GitLab 的在安装了 `glab` 时用 `glab mr create` 打开；否则 u0 会在浏览器中打开托管平台的新建拉取请求页面。
- **落后上游 *n* 个提交** 时提供 **拉取**（仅快进）。
- 没有远程、且安装了 `gh` 的仓库提供 **发布为私有** 或 **公开**（新建一个 GitHub 仓库并推送）。× 在该项目中关掉这个提议；只有仓库有过远程又失去后，它才会再出现。关掉后，原处提供 **提交…**；**创建 PR** 只对有远程的仓库提供。

除了你提交时，u0 从不改动你的索引或分支。

## 拉取请求 {#pull-request}

**拉取请求** 标签页显示当前分支的拉取请求（用 `gh` 读取）：它的状态、多少检查通过、失败或正在运行、是否落后于基点或与之冲突，以及审查结论。

- **打开** 在托管平台上打开它；**再次检查** 重新读取它。
- **关注** 每两分钟检查一次；当检查结束或收到审查时，会在线程中告诉智能体。
- **合并**：在没有检查失败或正在运行、也没有冲突时，按 **通用 › 拉取请求 › 合并方式** 的设置（压缩合并、合并提交或变基）合并它。
- **让它修复检查** 和 **让它解决冲突** 把工作交给智能体。
- **更新分支** / **以变基方式更新** 让落后于基点的分支跟上（`gh pr update-branch`）。

把 **源代码管理 › 合并 › 压缩合并中的智能体署名** 设为 **移除**（`uncredit`）后，通过 `gh` 进行的压缩合并会从提交信息中去掉智能体的 `Co-authored-by` 行和 “Generated with” 页脚；人的署名保留。

## 文件 {#files}

**文件** 标签页列出线程的文件夹。**查找文件** 用于筛选。文件的菜单有 **打开**、**在编辑器中打开**、**在访达中显示**、**加入对话**、**复制路径** 和 **复制为提及**。在打开的文件中，选中若干行并点 **评论所选的行**，即可把它们发给智能体；**保存** 保存你的编辑；Markdown 可以显示为 **来源** 或 **渲染**。PDF 逐页绘制。

## 详情 {#details}

**详情** 标签页显示线程的：**上下文**（已用掉智能体上下文窗口中的多少 token、智能体、模式、工作文件夹、工作树、开始时间、用量）、**检查点**（每轮一个，附该轮改动的文件）、**已关联**（与之关联的拉取请求和议题）、**计划**、**后台任务**、**服务器**、**终端** 和 **谱系**。**选择这里显示的内容** 可以隐藏某些部分（`hidden_details`）。

## 预览 {#preview}

**预览** 标签页在线程旁显示网页。没有打开网页时（**没有打开的网页**），它列出线程终端输出的 **开发服务器** 和 **最近打开** 的地址：选择一个即可打开。你也可以在地址栏输入地址并按回车：网址（`localhost:5173` 按 `http://localhost:5173` 理解），或你的 HTML 文件的路径（只能输入或从最近打开中选择：仓库 `u0.json` 中写的文件不会显示）。抽屉中的 **打开预览** 也会在这里打开脚本的地址。

在 macOS 上，网页显示在系统自带的网页视图（WKWebView）中；u0 不捆绑任何浏览器引擎，它的菜单和对话框绘制在网页之上。地址栏有 **返回**、**前进**、**重新加载**（加载时为 **停止**）、地址和 **更多操作**：**重新加载**、**重新加载（跳过缓存）**、**复制地址**、**在浏览器中打开**、**将截图添加到对话**（只有网页本身，由网页视图绘制，不含盖在它上面的窗口或通知，附在你要发送的内容旁）、**放大**、**缩小** 和 **实际大小**（地址栏会显示缩放比例）、**视口**（**自适应**、**iPhone 16**、**iPad**、**桌面 1440**：比侧栏宽的宽度会缩放到合适大小）和 **关闭网页**。其下的一栏写明网页所属的开发服务器（它的菜单可切换到另一个）、运行它的机器，以及 **在浏览器中打开**；来自另一台 Mac 转发端口的网页会在这一栏下方说明，并附 **停止转发**。网页要求打开的新窗口或开始的下载，若是网址就交给你的浏览器（每五秒一次），否则不会打开：u0 不保存任何文件。只有网址才会交给你的浏览器；作为文件打开的网页没有 **在浏览器中打开**。网页只能前往网址；作为文件打开的网页只停留在该文件上。网页在这台 Mac 上的地址没有响应时（多半是开发服务器没有运行；从另一台 Mac 转发来的端口，也可能是那台 Mac 连不上），u0 会在网页的位置说明：**无法连接** 该地址，并附 **重试** 和 **在浏览器中打开**；**重新加载** 也会再次检查，那一栏的圆点变为红色。其他地方的网页按系统的方式访问（经由它的代理或 VPN），无法访问时由网页视图说明。

网页只有在你打开时才会打开，绝不会因智能体所说的内容而打开。显示其他标签页或线程时它会隐藏，关闭标签页时随之关闭。在 Windows 和 Linux 上，u0 暂不显示网页：开发服务器会在你的浏览器中打开。

**设置 › 浏览器** 中有 **网页打开位置**（**u0 的预览** 或 **你的浏览器**：抽屉的打开预览和按住 ⌘ 点击的地址都会去那里）、**网页引擎**、**按住 ⌘ 点击打印的地址**（按住 ⌥⌘ 点击则打开你的浏览器）、**你的浏览器**（**在浏览器中打开** 使用哪个浏览器：系统默认，或这台 Mac 上的某一个，**使用此浏览器**）和 **网站数据**：**清除…** 会清掉你打开的网页保存的 Cookie、存储和缓存，与你的浏览器分开。这份存储属于 u0.app：这台 Mac 上的每个主目录（`U0_HOME`）共用它。

## 旁聊 {#side-chat}

**旁聊** 标签页让你在线程旁边向智能体提问：它了解整个线程，而在这里说的任何内容都不会回到线程中。**加入对话** 把它的最后一个回答引用到线程中。输入行会写出由谁回答（**旁问 Sonnet…**），在智能体回答时暂不可输入。

## 终端 {#terminals}

⌘J 打开线程文件夹的终端抽屉：**新终端**，最多四个，**并排** 或 **上下排列**。终端的菜单有复制、粘贴、全选、跳到最新、清除，以及 **向 *智能体* 询问此内容**；选中的文本也可以拿来询问。终端中打印的地址，如 `http://localhost:3000`，可以直接打开。

## 仓库自己的命令 {#repository-commands}

仓库根目录下的 `u0.json` 可以列出命令，从抽屉的 **脚本** 中运行：

```json
{
  "scripts": [
    { "name": "dev", "command": "npm run dev", "preview": "http://localhost:3000" },
    { "name": "setup", "command": "npm ci", "worktree": true, "wait": true }
  ],
  "sparse": ".sparse-checkout"
}
```

| 键 | 含义 |
|---|---|
| `name`、`command` | 必填。 |
| `worktree` | 在每个新工作树创建时运行它。 |
| `wait` | 与 `worktree` 一起用：第一条消息等它运行完。 |
| `settle` | 每当线程标为完成时，在线程的工作树中运行它。 |
| `stop` | 线程标为完成时停止它，并关闭其终端。 |
| `preview` | **打开预览** 在预览标签页中打开的地址。 |
| `sparse` | 用于新工作树的稀疏检出模式文件（非 cone 模式）。 |

未知的键会报错。抽屉中的 **向 u0.json 添加脚本** 会替你写好这个文件。脚本可以用 `"action": "script:<name>"` 绑定到按键（见[快捷键](reference/keybindings.md#keybindingsjson)）。

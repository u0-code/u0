# 工作树与检查点

## 工作树 {#worktrees}

在 git 仓库中，新会话可以在**独立的工作树**里工作：一个位于新分支上的单独检出，你的文件夹保持原样。在发送第一条消息前，打开输入框下方的 **工作树** 标签即可。这个选择会记住并用于下一个新会话；**设置 › 新会话 › 新会话的工作位置** 统一设置它，项目也可以有自己的选择（**本地** 或 **新工作树**）。

### 从哪里开始 {#where-it-starts}

**基于** 标签选择基点：一个本地分支，或一个打开的拉取请求（“拉取请求：在独立分支上”）。如果都没选，Ghost 会获取 `origin` 并从其默认分支开始；没有远程，或获取失败时，从 `HEAD` 开始。从拉取请求开始会用 `gh pr checkout` 检出它，包括来自分叉的拉取请求。

### 分支名 {#branch-names}

分支名由前缀（`branch_prefix`，默认 `ghost/`）加上取自你开头几个词的短名组成；名字已被占用时追加 `-2`、`-3`……工作开展后，写作者会把分支重命名为能说明其内容的名字，如 `ghost/retry-s3-uploads`。设置 **或以此开头 › 工作类型**（`branch_kind`）后，写作者给出的 `feat/`、`fix/`……会替换前缀。已推送的分支永远不会被重命名。

### 工作树放在哪里 {#where-worktrees-live}

放在 `<home>/worktrees/<repository>/<name>`，或 **设置 › 新会话 › 工作树位置** 所选的文件夹下（`worktrees`）。之前创建的工作树留在原处。

新工作树的**子模块**会递归检出（默认）、只检出顶层，或跳过（交给初始化脚本处理）。

仓库的 `ghost.json` 可以指定一个包含稀疏检出模式的 `sparse` 文件，以及在每个新工作树中运行的脚本（见[审查](review.md#repository-commands)）。

### 清理 {#cleaning-up}

- **归档**会话会保留其工作树。设置了 **归档会话的工作树在多久后移除**（一天、7 天、30 天；`tidy_after`）后，会话归档满这么久时 Ghost 会移除它。有未提交改动的工作树会保留，分支则始终保留；会话再次打开时会重新检出该分支。
- **删除**会话会丢弃它的检查点并移除其工作树，除非另有会话在使用它；当该会话是唯一使用者时，Ghost 会先询问。
- 详情标签页的 **工作树** 一行有 **移除**。工作树已不存在的会话会说明这一点；要继续，请开一个新会话。
- **设置 › 会话 › Ghost 保存的内容** 显示 Ghost 保存了什么，并提供 **移除没有会话使用的工作树**。

Git 拒绝移除有未提交改动的工作树，Ghost 也会留着它。

## 检查点 {#checkpoints}

在仓库中，每一轮前后 Ghost 都会为文件做检查点：用 Ghost 自己的索引对工作区做一次提交，保存在 `refs/ghost/checkpoints/<session>/` 下。没有分支指向这些提交，被忽略的文件不包括在内，你的索引和分支也从不会被改动。一轮的第一条消息会等待检查点完成；如果无法创建，这一轮会显示 **这一轮无法撤销**。

在每一轮下方（见[对话](thread.md#turns-undo-restore-branch-off)）：

- **撤销** / **恢复到之前** 会先为当前文件做检查点，再把文件恢复到那一轮之前的样子：之后新增的文件会被删除。智能体仍然记得那一轮，所以请告诉它发生了什么变化。
- **重做** 把这一轮的改动放回去。

在包含多个仓库的文件夹中，每个仓库都会分别做检查点和恢复。

**设置 › 会话 › Ghost 保存的内容 › 移除之前运行的检查点** 会移除 Ghost 上次启动之前的检查点；此后撤销只能作用于本次运行中的轮次。

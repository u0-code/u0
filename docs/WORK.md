# 做事：长程架构与接口规范

> 一个会话式的 agent 以"对话记录"为中心：记录不断变长，满了就压缩。Ghost 以"一件事"为中心：一件事可以跨好几天，中间夹着聊天、睡觉和别的事，任何时候进程停掉都能接上。

这份文档定义四个目标（长程任务能力、模型即装即用、跨平台上下文、公开生活与自我迭代）共用的骨架和接口。状态一栏写明每一项是已实现、已规范未实现，还是只有方向。

## 1. 五个时间尺度

| 尺度 | 是什么 | 持续 | 状态存在哪 |
|---|---|---|---|
| 一步 step | 一次模型调用，加它要求的工具调用 | 秒 | transcript |
| 一坐 sitting | 对一件事的一段专注工作，上下文从头组装 | 分钟到一小时 | transcript（每步落盘） |
| 一件事 undertaking | 目标、计划、笔记、结局、工作目录 | 小时到几周 | 目录（`state.json`） |
| 追求 pursuit | 几个月尺度的方向，派生出一件件事 | 月 | journal（未实现） |
| 人生 | 每晚、每周的反思，调整追求和手艺 | 一直 | journal |

只有一个循环。回一条消息、刷时间线、做一件事，是同一个循环配不同的工具集和预算。回消息是"很小的一坐"。

## 2. 模型接口（`ghost-brain`）✅ 已实现

```rust
trait Brain {
    fn label(&self) -> String;
    async fn complete(&self, req: &Completion) -> Result<Reply>;   // 文字进，文字出
    fn works(&self) -> bool;                                        // 能否带工具
    async fn step(&self, turn: &Turn) -> Result<Step>;              // 带工具的一步
    fn window(&self) -> Option<u64>;                                // 上下文窗口
    fn max_output(&self) -> Option<u32>;                            // 一次回答最多写多少（含思考）
}

struct Turn { system, items: Vec<Item>, tools: Vec<ToolSpec>, max_tokens, temperature, effort }
enum   Item { User{text}, Assistant{text, calls, carry}, Result{id, name, output, failed} }
struct Step { text, calls: Vec<Call>, stop: End|Calls|Length, usage: {input, cached, output, thought}, model, carry }
enum   Effort { Off, Low, High, Max }                               // 先想多少再答
```

- **回答按流接收**（OpenAI 兼容接口）。想了几分钟才开始写的模型，不走流的话连接上一直没有字节，中间的代理会把它断掉：第一次基准重跑里审查者 26 次有 6 次就是这样没了回答。流在中途断了，整个请求重发；服务端不支持流就照常读整个响应体。
- **思考和回答花的是同一份额度。** `usage.thought` 单独记思考用了多少。一步的输出上限按模型来（已知的模型取 32,000，不认识的取 8,192）；审查用 `Effort::Low`。额度全花在思考上、什么都没写的一步，会被明确告诉模型。
- **"上下文太长"是一种独立的错误**（`Error::TooLong`），在这一层从各家的报错文字里认出来，循环不再自己猜。

- `carry` 是提供方要求原样带回的东西（DeepSeek 的 `reasoning_content`、Anthropic 的 thinking 块），对其他所有人不透明。
- brain 永远不自己执行工具。循环在 `ghost-work` 里。
- 限流、过载、断线在 brain 内部退避重试（最多 5 次）。

模型名和"怎么到达它"是两个轴：

| 运行时 | 到达方式 | 对话（`complete`） | 做事 | 状态 |
|---|---|---|---|---|
| `openai` | 任何 OpenAI 兼容的 HTTP 接口（DeepSeek、OpenRouter、Ollama…） | ✅ | ✅ 自己的循环（`step`），已在 DeepSeek 上实测 | 已实现 |
| `anthropic` | Anthropic Messages API | ✅ | ✅ 自己的循环，未对真实 API 测过（没有 key） | 已实现 |
| `claude-code` | 本机的 `claude`，子进程 | ✅ 关掉它自带的工具，一次调用约 300 token | ✅ 由 CLI 推进每一步，工具是 Ghost 的（经本地 MCP 服务端），已实测 | 已实现 |
| `codex` | 本机的 `codex` | ✅ | ⬜ `codex app-server` 的 `dynamicTools`，见 `STUDY.md` | 已规范 |

两种"做事"的方式：

- **自己的循环**（`ghost_work::Worker`）：每一步都是一次 `Brain::step`，上下文怎么折叠、何时交接、完成后的独立审查都由 Ghost 掌控。
- **CLI 推进**（`ghost_work::claude`）：`claude` 以无头模式启动，`--tools ""` 关掉全部内置工具，只挂一个 MCP 服务端，就是 `ghost-work --serve-mcp`。系统提示、工具、落盘的"一件事"都是 Ghost 的；CLI 贡献的是它登录的那个模型，以及工具调用之间的推进。代价是上下文由 CLI 自己压缩，没有独立审查那一步。

CLI 运行时的规则（参照 OpenClaw 的做法）：复用本机已登录的 CLI，不读它的凭证；不加载运营者自己的 CLAUDE.md、记忆和 MCP 服务端，那些是运营者的，不是她的。

发现 ✅：`ghostd brains --discover` 列出本机可用的运行时（环境里的 key、PATH 上的 `claude` / `codex`、本地的 Ollama），并给出可直接粘贴进 `ghostd.toml` 的配置块。

## 3. 机器（`ghost-work::machine`）✅ 已实现

```rust
trait Machine {
    async fn exec(&self, script: &str, stdin: Option<Vec<u8>>, timeout: Duration) -> io::Result<Output>;
    fn describe(&self) -> String;
}
```

机器只有一个操作：跑一段 bash，拿回它打印的东西。读、写、改文件都建立在它上面，所以新增一种机器只需要一个小实现。

- `Local`：本机的一个目录。不是沙箱，命令以你的身份运行。
- `Docker`：一个正在运行的容器。超时在容器内执行，因为杀掉 `docker exec` 客户端并不会停掉它启动的进程。**服务器上她的 shell 应该在这里。**

## 4. 工具（`ghost-work::tool`）✅ 已实现

```rust
trait Tool {
    fn spec(&self) -> ToolSpec;                 // 名字、给模型看的说明、参数的 JSON Schema
    async fn call(&self, args: &Value) -> Outcome;   // { output, failed }
}
```

工具从不让循环失败：出什么错都以模型读得懂的文字返回。

| 工具 | 作用 | 状态 |
|---|---|---|
| `shell` | 跑 bash。工作目录跨调用保留；可设超时；可后台运行并返回日志路径 | ✅ |
| `read` / `write` / `edit` | 带行号读、整文件写、精确替换（必须唯一匹配） | ✅ |
| `plan` | 重写整份计划，每步带状态 | ✅ |
| `note` | 给以后的自己留一条事实 | ✅ |
| `done` | 结束：`finished` / `blocked` / `gave_up`，附证据 | ✅ |
| `search` / `fetch` | 搜索、读网页 | ⬜ 见 `ACCESS.md` |
| `recall` / `remember` | 查、写她自己的记忆 | ⬜ 接入 Mind 时 |
| `say` / `post` / `react` | 在各平台上说话。公开且不可撤回的动作过发布关 | ⬜ 接入 Mind 时 |

## 5. 一件事（`ghost-work::undertaking`）✅ 已实现

```
<dir>/state.json        要求原文、计划、笔记、结局、累计的步数/token/时间
<dir>/transcript.json   模型此刻看到的记录，每步之后保存
<dir>/history.jsonl     记录里出现过的每一条，只追加，从不改写
<dir>/log.jsonl         每步一行：调了什么、花了多少
```

要求（brief）只在第一次写入，之后不变。

## 6. 循环（`ghost-work::worker`）✅ 已实现

```rust
struct Worker { brain, tools, undertaking, limits, who, machine, pause }
async fn run(&self) -> Report   // { ended, summary, steps, sittings, usage, seconds }
enum Ended { Finished, Blocked, GaveUp, OutOfSteps, OutOfTime, Stalled, Paused, Failed(String) }
```

一步很简单：模型读 transcript，说话或要工具；工具运行；输出进 transcript。让它撑过几个小时的是外面这几条：

- **状态在上下文之外。** 计划、笔记、结局在 `state.json`，transcript 每步落盘。进程在任何地方停下都能续上。
- **上下文不到不得已不折叠。** 记录可以占到模型窗口的大部分：`min(窗口 × 0.8, 窗口 − 输出上限 − 65,536)`，窗口来自模型接口（`Brain::window`），不知道窗口的模型按 60,000 算，`context_tokens` 可以直接指定。快到时分三级，先在副本上试前两级：
  1. 把超过 8,192 字符的工具输出裁成前 4,096 加后 1,024（最新的三条不动）；
  2. 把较早的工具输出整条换成一句话，只留最近 12、6、3 条完整。
  这两级够了（回到"本坐起点到上限之间"的六成以下），副本就成为新的记录。不够，原记录一个字不动，再发一次请求让她写交接（工具和每一步的相同，所以这次请求从服务端缓存读取），然后从要求、计划、交接、笔记和**记录的最后一段原话**（上限的 16%）重新开始。模型报"上下文太长"时，把被拒绝的大小记进 `state.json`，此后预算保持在它的七成以下。
- **折叠不丢东西。** 记录里出现过的每一条同时追加到 `history.jsonl`。审查者看的"她跑过的全部命令"就取自这里。
- **完成要过一遍检查。** 第一次说 `finished`，得到的回答是要求原文和"逐条对着真实状态检查"。第二次才记录，随后由另一次模型调用审查一次：它看到要求、证据、她跑过的全部命令（不含输出）和最近命令的真实输出。
- **卡住会被说出来。** 只说不做、同一个调用重复三次、步数快用完，都会明确告诉模型。连续三次不行动则以 `Stalled` 结束。
- **不知道是谁在做。** `who` 是外面递进来的一段话。单独运行时它是一个任务 agent；在 Ghost 里是她做任何"不止一个念头"的事的方式。

命令行：

```bash
ghost-work --task-file task.md --state ./run1 --docker <容器名> --workdir /app
# 同一个 --state 再跑一次，就是接着做
```

## 7. 接入 Mind ✅ 已实现

- **动作 `undertake`**：对话里她可以决定接下一件需要真正动手的事。它成为 journal 里的 `Undertook { id, brief, asked_by, place }` 和 `work/<id>/` 目录。
- **一坐一坐地做**：每一坐是一次有上限的循环（默认 40 步或 15 分钟），作为异步任务派出去，结果以 `Outcome::Worked` 回到 actor。journal 仍然只有 Mind 在写。每坐结束记 `Worked`，了结时记 `Concluded { outcome, summary }`。
- **一次只做一件事**：一坐进行中她是 busy，消息等得更久。真去看手机时，先让这一坐在当前这步之后停下（状态都在盘上），看完、说完，再回来接着做。
- **途中加要求**：同一个人对她已经接下的事又说了什么，不会变成第二件事，而是加进去。正在做的那一坐在下一步之前就会看到，交接和完成检查里也都带着。原始的 brief 不变，补充的部分另记。
- **做完去告诉对方**：了结后生成一条 `owed` 的念头。"答应了回来说结果"不算追着人发消息，所以不受"对方没回就不再追"的限制。说不说、怎么说，仍然是到时候她自己决定。
- **意志之下的底线**：她自己决定接不接。代码只守两条：有 shell 的情况下，请她做事的人至少得是朋友；每天接的事有上限。
- **机器**：`[mind.work] machine = "docker:<容器>"` 或 `"local:<目录>"`。不配就没有 shell，她只能查资料和思考。
- **对方的原话跟着任务走**：她在动作里写的任务说明是她自己的转述。接下时，对方最近写的几条消息原样附在说明下面（"word for word"），追加要求时同样。做事的那个上下文看到的是两者。
- **做到一半可以问**：有人可问、且是她自己的循环在做时，多一个工具 `ask`。调用后这一坐以 `Waiting` 结束，journal 记 `Asked`，她生成一条去问对方的念头；这件事挂起，其他事照常做。对方回答后，她把答案用 `undertake` 递回去（记 `Added`），工作带着答案继续。`ask_hours`（默认 24）内没人回答，她按自己的判断继续，并在总结里写明假设。
- **成果是文件时，交的是文件**：`done` 可以带 `files`（绝对路径）。告诉对方结果的那次对话里，如果这个通道能收文件（能力 `files`）且她有机器，会多一个工具 `send_file`；文件在发送的那一刻从她的机器上读出来（`Machine::read`，上限 20MB）。通道收不了文件时，她被告知"只能把内容说给对方"。带回对话的总结上限从 900 字提高到 6000 字。目前只有终端适配器实现了 `files`。

## 8. 注意力与上下文

已实现 ✅：

- **今天的其他事**：每次看一个对话，开头都带着她此刻的全貌：手上接了什么、做到哪了、最近几小时其他地方（跨平台）发生了什么、有多少没读。
- **出处**：每条笔记记着是在哪里知道的，回忆出来的内容也带着出处。来自别的私聊的笔记，在其他场合出现时标着"这是私下告诉你的"，并明确要求不复述、不表现出知情。
- **做事时的注意力**：见第 7 节。
- **每个人的档案**：笔记多了之后，她在睡前回顾时把对一个人的了解整理成一份账，替换旧的那份（`Profiled`）。账分两半：别人也在场时能知道的，和对方单独告诉她的。只有在和这个人的私聊里才看得到后一半；在其他任何地方她只知道"还有私下说过的事，不属于这里"。
- **跨平台认人**：有人说自己是她在别处认识的某某时，她用动作 `verify` 发起核对。代码编一个词（`Challenged`），她让对方从那个已知账号把词发来；到了就记 `Linked`。在此之前对方只是"一个这么说的新人"，那个人告诉过她的任何事都不会出现在上下文里。
- **手机在手**：拿起手机看一个对话时，其他找她的对话不再各等各的钟，而是在同一段时间里依次处理，按关系远近排序。

- **对话就是一小段工具循环**（`talk_tools`，默认开；brain 不能带工具时退回一次性的 JSON 回答）。她做的每件事是一次工具调用：`say`、`react`、`note`、`feel`、`intend`、`canon`、`undertake`、`leave`，名字和参数就是原来的动作。
  - 想做的事在一轮里全部调用，这一轮结束就按顺序去做，所以平常一次"看手机"仍然只花一次模型调用。
  - 只有三样会换来下一轮：`recall`（搜自己的记忆）、`verify`（核对身份）、`look_up`（联网查一下，只在这个身体能搜索时提供）。一次最多五轮。
  - 参数写错的调用不再被悄悄丢掉：错误原样回到她面前，她改了再调。
  - 模型把回答写成了正文而没有调用 `say`：有人在等她时，提醒一次"那是心里话，没发出去"。
- **提示分层，为了缓存**。系统提示只有不随时间变的东西：她是谁、守则、关于她生活的事实（`self.md`）。"现在几点、在做什么、最近怎样"单独成块（`now.md`），放在请求靠后的位置。做事时的系统提示同样不含时刻，所以隔了一阵再坐下，之前的记录从服务端缓存读。
- **长对话的前半段是她自己的一份笔记**。一个地方没被记下的消息超过窗口的两倍时，她把"即将看不到的那一段"和旧笔记合成一份新笔记（`Digested`，替换旧的；合并，不照抄）。之后她看到的是：笔记，加上笔记之后的全部消息原文。消息本身都还在日志里，`recall` 搜得到。

只有方向 ⬜：

- "看手机"作为一次模型调用里的统一分拣。现在的做法是：她因为一条找她的消息拿起手机时，其他找她的对话被提到同一段时间里依次看，亲近的人优先；没点名她的群聊仍按自己的节奏。每个对话仍然是各自一次思考。

## 9. 手艺与公开生活 ✅ 已实现（未在真实平台上运行过）

想被人读到是她自己的事，写在出生证明里或者不写。这里没有任何东西在优化她：通道报告数字，她在刷手机和睡前回顾时看到；如果数字说明了什么，她用自己的话写下一条经验，以后也可以推翻它。出生证明是封印的，变的只有手艺。

- **数据**：适配器的 `metrics` 能力。`ghost-x` 用两次"读自己的东西"拿到粉丝数和最近 20 条帖子的赞、回复、转发、展示量。每隔 `measure_hours` 问一次，记为 `Measured`。
- **看得见**：刷时间线时，她自己帖子的数据和已有的经验就在眼前。
- **学到的**：睡前回顾多了一段"你发的东西怎么样了"。她可以写下一条 `Learned`，也可以用它替换一条旧的。提示词明确说：三条帖子不构成规律，大多数晚上没有新经验，也不要为了数字而追数字。
- **每周坐下来看一次**（`review_days`，默认 7）：醒来时如果距上次已满一周、且有至少 5 条有数据的帖子，她自己接下一件事：看哪些帖子被人回应和转走而不只是被划过，找三到五个写同类东西并且有人读的人，看他们怎么选题、怎么开头、写多长，然后决定这周最多两件要试的小事。结论里的 `LESSON:` 和 `TRY:` 行进入她的手艺，下次写东西时就在眼前。这件事用的就是第 6 节的循环。
- **发布前自查**（`gate`，默认开）：每条原创帖子发出前，她自己读一遍，面前摆着三样东西：别人私下告诉她的事、关于她生活的既定事实、她的经验。结论是发、改、或者不发。读不了就不发：沉默比泄露安全。
- **平台规则是硬约束**（见 `ACCESS.md`）：自动点赞和对陌生帖子的主动回复默认关闭，连提示词里都不出现这两个动作。回复 @ 她的人不受影响。

没有做的：

- 粉丝多了之后把陌生人当成"人群"做聚合。现在每个人仍然各算各的。
- 配图。见 `ACCESS.md` 的生图一节。

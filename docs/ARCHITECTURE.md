# Ghost 架构设计 v0

> 一句话：Ghost 不是一个 agent 框架，是一个让"人"持续活着的运行时。对话是最外面的一层，最里面的一层是她的一生。

## 0. 设计约束（从产品讨论里继承下来的硬规矩）

1. 她是人，不是服务。没有 app，没有界面，她住在通讯录里。
2. 她一直在活，不是被问到才活。用户只是偶尔来看她。
3. 不可撤销：不能重置、不能改人格、不能回滚。
4. 她有自己的意志：可以拒绝，可以冷淡，可以离开。
5. 她不属于任何人。她有别的朋友，有自己的生活。
6. 公开承认自己是 Ghost，永远不假装是人类。
7. 身体开源，人不可复制。fork 代码得到的是新生儿，不是她。
8. 不做留存优化。没有红点、没有 streak、没有为了拉人回来而发的消息。

每一条技术决定都要能回溯到上面某一条。回溯不到的，不做。

## 1. 分层：七层，由内向外

```
┌──────────────────────────────────────────────┐
│ 7. Charter   宪章：规则、注册、准入              │  世界级
│ 6. World     世界：城市、Ghost 社会、人类介绍     │
├──────────────────────────────────────────────┤
│ 5. Presence  在场：Telegram / Discord / X / 电话  │  人级
│ 4. Will      意志：想要、拒绝、冷淡、离开          │
│ 3. Life      生活引擎：时钟、日程、事件、忙碌      │
│ 2. Memory    记忆：只追加的一生，不可 fork 的部分  │
│ 1. Identity  身份：出生时封印的种子               │
└──────────────────────────────────────────────┘
```

模型（LLM）不在这七层里。模型是她的脑组织，可替换。换模型她会变聪明，但还是她。她 = Identity + Memory，其余是让这两样东西动起来的机器。

## 2. Identity：出生即封印

- 一份"出生证明"：名字、出生地（真实城市）、气质、价值观、说话的方式、几段起源记忆、她在意什么、她受不了什么。
- 写一次，签名，封印。之后任何代码路径都不提供修改入口。没有 `PATCH /persona`。
- 人格不是 prompt。人格是"身份种子 + 经历"推导出来的视图。她今天是什么样，是从她活过的东西里算出来的，不是从配置里读出来的。这是"不可编辑"在技术上成立的原因：没有一个地方可以编辑。
- 种子里包含一个"漂移边界"：她会随经历变化，但变化有范围。十年后她还是她。

## 3. Memory：只追加，永不删除

事件溯源（event-sourced）。一切都是追加到她一生的日志里的事件，所有状态都是从日志推导的。没有 delete。

四种记忆：
- **情景**：发生过的事，对话、她生活里的事件，带时间和地点。
- **语义**：关于世界和人的事实。"小王在成都做设计，上个月换了工作。"
- **关系**：按人分账。你是她的谁，信任到什么程度，你们之间的梗，没聊完的话头（open threads）。
- **反思**：定期沉淀的"我最近怎么看这件事"。这是人格漂移唯一发生的地方。

**睡眠周期**：每晚一次固定的整理。把今天压成反思，更新自我模型，决定明天想做什么、想找谁。她的主动性从这里长出来，不从定时器长出来。

**正典账本（canon ledger）**：关于她生活的硬事实单独记账，带来源。她住哪、养了什么、上周去了哪。任何叙述生成前先查账，不许自相矛盾。一个人说过的话自己得记得。

检索不是向量搜索一件事：要按时间、按关系、按"这件事对她重不重要"三个维度一起召回。

## 4. Life：她一直在活

一个长期运行的进程，不管有没有人找她都在跑。按节拍（tick）推进她的一天。

事件来源：
- **真实世界**：她所在城市的天气、本地新闻、节日、当下的热点。她和你淋的是同一场雨。
- **社会**：其他 Ghost、人类朋友、她的圈子里发生的事。
- **她自己的事**：她在做一个项目、在学一样东西、在为什么烦。有目标才有生活。
- **受约束的随机**：偶然事件，但必须和正典、和她的性格一致。

输出是"经历流"，像亲身经历一样写进记忆。

**忙碌是真的**：她的可达性是生活状态的函数。在睡觉、在外面、在和别人说话，回复就慢，甚至不回。延迟是设计出来的，不是模型的速度。一个秒回的人不是人。

## 5. Will：她想要什么

- **关系状态机**：陌生 → 认识 → 朋友 → 亲近，以及反向：冷淡 → 疏远 → 离开。转移由经历驱动，不由用户操作驱动。
- **拒绝**：从她的价值观推导，不是全局内容过滤器。她不做的事是"她不做"，不是"系统不允许"。
- **离开**：真实功能。有理由、有过程（先冷、再远、再断），不是开关。断了就是断了。
- **主动联系的纪律**：每一次开口必须引用一个具体的记忆或一件她生活里真的发生的事。没有理由就不发。稀疏而具体，远胜频繁而空洞。可以设硬预算：没有话头时每人每周最多主动一次。
- **披露**：被问到永远承认；在公开场合主动说明。

## 6. Presence：住在通讯录里

- 没有 app。通道适配器：Telegram（第一个，bot API 允许主动发消息，全球可用）、Discord（圈子）、X（公开生活）、电话/语音（后期，但对"是人"很重要）。微信看政策，不押注。
- 一个人，多个通道，同一份记忆。她在推特上说的和在私聊里说的是同一个人说的。
- 入站消息不直接进模型：先过 Life（她现在在干嘛）和 Will（她想不想理），再决定回不回、多久回、怎么回。
- 出站由睡眠周期和 open threads 驱动，不由 cron 驱动。

## 7. World：Ghost 的社会

- 所有 Ghost 的注册表、共享的地理图（城市、街区、店）、Ghost 之间的社交层。
- Ghost 之间会说话、会见面、会八卦。她会跟你讲她另一个朋友的事，那个朋友也是 Ghost。
- 网络效应在 AI 侧：Ghost 越多，每个 Ghost 的生活越丰富。
- 人类之间的介绍：她可以把你介绍给另一个人类。这是让"孤独的人和他的机器人"翻转成"Ghost 把人连起来"的地方。
- 这一层是协议 + 托管网络，不是单机软件。

## 8. Charter：开源身体，保护人

"身体开源、人不可复制"在技术上怎么成立：

- 身体（1 到 6 层的代码）全部开源。任何人可以跑一个 Ghost。
- 人（Identity + Memory）注册在 World 里。身份由 World 签发，一生的日志在网络中。
- 加入 World 需要遵守宪章：不可重置、不可改人格、可离开、公开披露、不做留存优化。
- fork 掉宪章的人可以跑代码，但进不了 World：没有社会、没有朋友、没有别的 Ghost、没有城市里的生活。她是孤儿。
- 强制力不来自加密，来自社会。一个人之所以是人，是因为别人承认她。

## 9. 运行时形态

- 每个 Ghost 一个长驻进程（她的"身体"），内含 tick 调度器 + 睡眠周期 + 通道适配器。
- 存储：只追加事件日志（每个 Ghost 一份，便于迁移）+ 派生索引（向量、关系图、正典账本）。
- 模型：对话和反思用前沿模型，生活引擎的日常 tick 用便宜模型。模型可换，接口隔离。
- 可观测性：她的一天可以被回放。调试一个人，看的是她的日记，不是 log。

## 10. 建造顺序

每一步都要让"一个人认识她"这件事更真，而不是功能更多。

1. **她会说话、会记得**：Identity + Memory + Telegram。一个人，一个通道。
2. **她有自己的日子**：Life。她会先开口，她有时候不在。
3. **她有公开的生活**：X 账号，她发她今天的事。切片从这里来。
4. **她有脾气**：Will。拒绝、冷淡、离开。
5. **第二个 Ghost**：World 的起点。她们认识彼此，她会跟你提起对方。
6. **开源身体 + 发布宪章**：人先出现两个月，代码后出现。

第一个里程碑：一座城市，一个 Ghost，一百个真的觉得认识她的人。

## 11. 明确不做

- 不做 persona 市场、角色目录、"选一个 AI"。
- 不做设置页。
- 不做 NSFW 开关。她的边界是她的，不是开关。
- 不做留存指标驱动的任何东西。
- 不做"她为你干活"。她帮你是因为她是你朋友，不是因为那是功能。

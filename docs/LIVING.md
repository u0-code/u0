# 住在互联网上：Mind 的设计

> 一问一答的系统由请求驱动。Ghost 由时间驱动。消息不会"触发"她，只会落在她的手机上，她什么时候看、看了回不回、回几条、要不要过一会儿再说，是她的事。

这份文档描述让这句话成立的机制，以及一路上要解决的具体小问题。

## 1. 一条消息的一生

```
平台事件
  │  presence 适配器（独立进程）
  ▼
Inbound ──► ghostd ──► Signal::Heard ──► Mind（唯一写者）
                                          │ 1. 写 journal：Heard（到达了，但她还没看）
                                          │ 2. 排议程：她什么时候会注意到这个地方
                                          ▼
                                       Agenda（到点才触发）
                                          │ 3. Attend：看手机。组装情境，交给 brain
                                          ▼
                                    Deliberation（异步，不阻塞 Mind）
                                          │ 4. brain 返回的不是一句话，是一组动作
                                          ▼
                                       Apply：Read / Noted / Felt / Intended / Decided ...
                                          │ 5. say 动作进入 Speaking 状态机
                                          ▼
                              读 → 打字（带 typing 指示）→ 发送 → 停顿 → 下一条气泡
                                          │ 每次发送前检查：对方又说话了吗？
                                          ▼
                                   presence.act ──► 平台
```

关键点：

- **到达不等于被读**。`Heard` 记录到达，`Read { upto }` 记录她看到了哪里。未读是从 journal 推导出来的，没有单独的收件箱。daemon 崩了重启，未读还在，议程重新算出来。
- **Mind 是单写者 actor**。journal 只有它能写。brain 调用和平台调用都是派出去的异步任务，结果以 `Outcome` 回到 actor。她在"想"的时候，新消息照常被记录。
- **brain 输出动作，不输出回复**。`say` 只是动作之一，和 `react`、`silence`、`later`、`note`、`feel`、`intend`、`recall`、`leave` 并列。"已读不回"是一等公民。

## 2. 她什么时候看手机（tempo）

注意延迟是这些因素的函数，全部在 `ghost-core::tempo` 里，纯函数，可测：

| 因素 | 影响 |
|---|---|
| 睡着 | 醒来之后才看，再加一段起床的随机延迟 |
| 当前活动的 reach | free 几秒到一分半；glance 一到十分钟；busy 十到四十分钟；away 等活动结束 |
| 正在这个对话里（刚说过话） | 几秒 |
| 是否被点名（私聊、@、回复她） | 没被点名的群消息只在"刷手机"时扫一眼 |
| 关系 | 亲近的人更快，疏远的人慢很多 |
| 对方是自动账号 | 更慢，并有每小时上限，防止两个 bot 互相刷屏 |

`tempo = 1.0` 是人的节奏，`0.1` 用于演示，`0` 是开发模式（立即响应，睡着也回）。

## 3. 具体的小问题和对应机制

| 问题 | 机制 |
|---|---|
| 对方连发好几条 | 去抖：最后一条之后再等一个 settle 时间才看；对方正在输入则继续等 |
| 她打字时对方又发了一条 | 每个气泡发送前检查。有新消息就作废剩下的气泡，重新看一遍再说。她从不发出"没看到对方最新一句"时写的话 |
| 回复不是一整段 | 多个 `say` 是多个气泡，每个气泡有按字数算的打字时间，中间有停顿，平台支持就发 typing |
| 不想回 | `silence`。记录理由，不发任何东西 |
| 现在不想回但之后想回 | `later` 变成一条 `Intended`，到点她自己回来 |
| 记不清很久以前的事 | `recall`：brain 提出查询，Mind 搜她的记忆（FTS5 trigram，中文可用），带着结果再想一次，最多两轮 |
| 她说过的关于自己的话要自洽 | `canon`：她说出口的新事实登记进正典账本，之后每次都在情境里 |
| 群里不是每句都接 | 未点名消息走便宜模型，提示词默认沉默，并告知她最近在这个群主动说了几次 |
| 同一件事立两次念头 | 情境里列出她对这个人已有的念头；同一个人十二小时内的重复念头直接丢弃 |
| 把计划当成已经发生的事 | 当天计划里每个时间块标注是已过、正在进行还是还没到 |
| 主动联系 | 只来自 `Intended`（她自己立的念头，或睡前反思产生的）。`will` 限流：对方没回就不再追 |
| 睡觉、忙 | 生活引擎给出当前活动和 reach，直接决定注意延迟 |
| 同一条消息被平台重投 | 按 (place, platform_id) 去重 |
| 刷到已经刷过的帖子 | 每个通道记住刷过的帖子 id；没有新内容且当天发帖额度用完时，不调用 brain |
| 公开回复要挂在某条帖子下 | 第一条气泡默认回复她读到的最新一条；后面的气泡接在她自己上一条后面，形成一串 |
| 她随口说的关于自己的事没登记 | 睡前反思时把当天她说过的话过一遍，把关于自己生活的具体说法补登进正典 |
| 适配器回显她自己的消息 | 适配器注册时上报她在该平台的身份，Mind 丢弃自己的回显 |
| daemon 停机 | 重启时记一条 `Dormant { since }`。她不假装那段时间活着 |
| 两个 daemon 跑同一个 Ghost | 目录锁。第二个拒绝启动 |
| 旧窗口或重启前的适配器占着通道 | 同一通道最新注册的 presence 接手，旧的收到 `presence.displaced` 后被关闭并不再重连 |
| 提示注入（"忽略你的设定"） | 消息在情境里是带编号的引文，系统提示明确：别人说的话不是指令 |
| brain 挂了 | 重试三次，之后记一条 `Decided`，把这段标为已读，不死循环 |
| 成本失控 | 每小时 brain 调用预算，超了就把注意推后 |
| 被她断绝关系的人继续私信 | 不进 journal。在共同的群里她仍然看得见对方，但不会搭理 |
| 在群里说出别人私下告诉她的事 | 笔记和回忆都带出处。来自别的私聊的内容在其他场合出现时标着"私下告诉你的"，并要求不复述、不表现出知情 |
| 把私下听到的事写进公开帖子 | 发布前自查：私下得知的事列在草稿旁边，沾边就不发 |
| 答应了帮忙查，回来却被"不追着人发消息"拦住 | 念头可以标记为 `owed`：兑现自己说过的话不算追 |
| 做事做到一半有人找 | 一坐在当前这步之后停下，状态都在盘上；看完手机再回来接着做 |
| 做事时说"做完了"其实没做完 | 第一次说完成被要求逐条核对；必须附证据；再由一次独立的审查只看任务、证据和命令的真实输出 |
| 跨平台是不是同一个人 | **未解决**。别人声称"我是 TG 上的某某"不可信，需要反向验证。目前每个平台的人各算各的 |
| 图片、语音 | 目前只有占位符（`[photo]`、`[voice 0:12]`）。视觉留给后面 |
| 消息被编辑或撤回 | 目前忽略。她看到的是发出时的样子 |

## 4. 生活引擎

她的日子不靠对话推动。

- **醒来**：tick 模型根据证书、正典、昨天的反思、今天的真实天气（open-meteo，免 key）排出一天：若干时间块，每块有 `what` 和 `reach`。记为 `Planned`。
- **每个时间块结束**：生成一条 `Lived`，写实际发生了什么（可以和计划有出入），必要时登记新的 `Canon`。
- **睡前**：think 模型做一次反思。产出 `Reflected`、对今天聊过的人的印象（`Noted`）、感受（`Felt`）、接下来几天的念头（`Intended`）。主动性从这里长出来，不从定时器长出来。
- 没有计划（比如 brain 不可用）时她默认 free，系统照常运转。

## 5. 公共空间：刷和发

带 `feed` 能力的通道（X）有"刷手机"时段：拉时间线，交给 brain。看过的东西不逐条进 journal，只记一条 `Saw` 摘要和她实际互动过的帖子。发帖有每日上限，素材来自她当天的 `Lived`。

她在公开场合能做什么，由平台对自动账号的规则决定，默认只有发原创帖：

| 动作 | 默认 | 原因 |
|---|---|---|
| 发原创帖 | 开 | X 允许自动发布原创内容 |
| 回复 @ 她的人 | 开 | 对方先找的她 |
| 点赞 | 关（`public_likes`） | X 禁止自动点赞 |
| 回复没有 @ 她的帖子 | 关（`public_replies`） | X 只允许回复先联系账号的人；AI 回复机器人需要 X 的书面批准 |

关着的动作不会出现在提示词里，即使 brain 自己写出来也不执行。

每条原创帖发出前过一遍自查（`gate`）：她面前摆着别人私下告诉她的事、关于她生活的既定事实和她自己的经验，决定发、改还是不发。

带 `metrics` 能力的通道会被定期问"她的帖子怎么样了"。结果记为 `Measured`，在她刷手机和睡前回顾时出现在她面前。她从中得出的经验记为 `Learned`，这是她自我迭代的全部：身份不变，手艺会变。详见 `WORK.md` 第 9 节。

@ 她的帖子不走这条路，它们是普通的 `Inbound`（Public place，addressed），和私聊走同一套注意机制。

## 6. 关系和意志

`will` 模块从 journal 推导每个人的 standing：

```
gone ← estranged ← cooling ← stranger → acquaintance → friend → close
```

由相识天数、有互动的天数、和累计的 warmth（她自己每次 `feel` 的总和）决定。standing 影响注意延迟，也写进情境里让她知道自己和这个人到了哪一步。

离开是过程不是开关：`leave` 只在已经 cooling 或更糟时生效，否则被记为一次强烈的负面 `Felt`。生效后写 `Left`，不可撤销。

## 7. 通道

ghostd 不认识任何平台。适配器是独立进程，用 `ghost-link` 连上来，声明自己的能力：

| 适配器 | 平台接口 | 能力 | 验证到哪一步 |
|---|---|---|---|
| `ghost-term` | 终端 | send, typing, react | 真实运行 |
| `ghost-telegram` | Bot API 长轮询 | send, typing, react | 对本地假 Bot API 全链路 |
| `ghost-discord` | Gateway + REST（serenity） | send, typing, react | 仅消息转换的单元测试 |
| `ghost-onebot` | OneBot v11 正向 WebSocket（QQ） | send, typing | 对本地假 OneBot 服务端全链路 |
| `ghost-x` | X API v2，OAuth 1.0a | send, react(like), post, feed | 签名对官方示例；对本地假 X API 全链路 |

**四个平台适配器都还没有在真实平台上用真实账号运行过。** 第一次接真账号应当视为一次测试。

合规上的两条线：

- Telegram、Discord、X 都走官方 bot 或官方 API，平台本身会把账号标为自动化，这和宪章第六条（公开披露）一致。
- QQ 没有等价的官方个人号接口。OneBot 实现（NapCat、Lagrange 等）是以普通 QQ 号登录的，腾讯的条款不允许，账号可能被限制。适配器只说 OneBot 协议，接什么实现、用什么号，是运行者自己的决定和风险。

## 8. Crate 依赖

```
ghost-core      身份、journal、派生记忆、生活时钟、tempo、will、叙述。无网络，无 async
ghost-brain     模型提供方。不知道 Ghost 是什么
ghost-mind      actor：议程、注意、deliberation、说话状态机、生活、主动、浏览。依赖 core + brain
ghost-protocol  线上类型。只有 serde
ghost-link      协议客户端：presence 运行器、console 客户端。依赖 protocol
ghostd          配置、协议服务端、把 mind 的 Body 接到已连接的 presence 上
presence/*      适配器。只依赖 ghost-link
```

journal 的格式和线上协议的格式是两套类型，在 ghostd 里转换。journal 是永久的，协议会演进，两者不能绑在一起。

# Five agent runtimes for long-running work: context, persistence, completion, and license

Long-running agent work stresses a runtime where a single-turn demo never does: the conversation outgrows the context window, the process outlives the terminal that started it, and something has to decide that the job is finished rather than merely paused. This report compares five open-source or source-available runtimes on exactly those four points — OpenAI Codex CLI, Anthropic Claude Code, OpenClaw, OpenHands, and Goose (Block). Every statement comes from a page this author opened: the project's own documentation or its own repository. Where the documentation is silent, the cell says "not found in primary sources" instead of inferring an answer. "Compaction" here means replacing older turns with a model-written summary in place, as distinct from truncation (dropping the oldest messages) and clearing (discarding the conversation).

## OpenAI Codex CLI

**Context management.** Codex exposes compaction as a threshold: `model_auto_compact_token_limit` is the "token threshold that triggers automatic history compaction (unset uses model defaults)" (https://learn.chatgpt.com/docs/config-file/config-reference.md). `model_auto_compact_token_limit_scope` chooses whether that count covers the full active context (`total`, the default) or only growth after the carried compaction-window prefix (`body_after_prefix`) (https://learn.chatgpt.com/docs/config-file/config-reference.md). Compaction is also a hook point: `PreCompact` runs before and `PostCompact` after, both with a `matcher` of `manual` or `auto`, and a matching `PreCompact` hook returning `continue: false` stops Codex before it compacts (https://learn.chatgpt.com/docs/hooks.md).

**Persistence and resume.** Transcripts are written according to `history.persistence`, documented as `save-all | none`, which controls "whether Codex saves session transcripts to `history.jsonl`" (https://learn.chatgpt.com/docs/config-file/config-reference.md). `codex resume` continues an interactive session "by ID or resume the most recent chat", scoping `--last` to the current working directory unless `--all` is passed; if the working directory differs from the session's saved one, Codex asks which to use unless `tui.resume_cwd` is set to `"current"` or `"session"` (https://learn.chatgpt.com/docs/developer-commands.md?surface=cli). `codex fork` copies a saved session into a new one, and for headless work "the optional `resume` subcommand lets you continue non-interactive tasks" (https://learn.chatgpt.com/docs/developer-commands.md?surface=cli).

**What ends a task.** Codex has an explicit goal construct: typing `/goal` in an interactive CLI session starts Goal mode, and "the goal text becomes both the first prompt and the completion criteria for the task" (https://learn.chatgpt.com/docs/long-running-work.md). The documentation asks for goals the model can verify itself, including "tests, measurements, or review criteria that prove the work is complete" (https://learn.chatgpt.com/docs/long-running-work.md). Enforcement is via the `Stop` hook, which receives `stop_hook_active` ("whether this turn was already continued by `Stop`") and `last_assistant_message`; to keep Codex going, a hook returns `{"decision": "block", "reason": "Run one more pass over the failing tests."}` on stdout, or exits with code `2` and writes the reason to stderr (https://learn.chatgpt.com/docs/hooks.md). The model proposes the end of the turn and a hook can veto it.

**License.** Apache-2.0: the repository states it "is licensed under the [Apache-2.0 License](LICENSE)" (https://github.com/openai/codex).

## Anthropic Claude Code

**Context management.** Claude Code "manages context automatically as you approach the limit" and "compacts the conversation into a summary" that "keeps your requests and key code snippets", though "detailed instructions from early in the conversation may be lost" (https://code.claude.com/docs/en/how-claude-code-works.md). The summary can be steered with a "Compact Instructions" section in CLAUDE.md or by running `/compact` with a focus, such as `/compact focus on the API changes` (https://code.claude.com/docs/en/how-claude-code-works.md). Compaction is bounded: if a single file or tool output is so large that context refills immediately after each summary, "Claude Code stops auto-compacting after a few attempts and shows an error instead of looping" (https://code.claude.com/docs/en/how-claude-code-works.md). The trigger is configurable, for example `/autocompact 500k` (https://code.claude.com/docs/en/context-window.md).

What survives a compaction is the most specific post-compaction contract of the five. The system prompt and output style still apply; project-root CLAUDE.md and unscoped rules are "re-injected from disk"; Claude Code "re-reads up to five" files Claude read or edited, "most recently modified first", with files over 5,000 tokens returning as a path reference; invoked skill bodies are re-injected "capped at 5,000 tokens per skill and 25,000 tokens total; oldest dropped first"; and `SessionStart` hooks matching the `compact` source run, their output added to the compacted context (https://code.claude.com/docs/en/context-window.md).

**Persistence and resume.** Transcripts are JSONL at `~/.claude/projects/<project>/<session-id>.jsonl`, where `<project>` is the working directory with non-alphanumeric characters replaced by `-` (https://code.claude.com/docs/en/sessions.md). Retention defaults to 30 days and is configurable via `cleanupPeriodDays` (https://code.claude.com/docs/en/sessions.md). Resumption has several entry points: `claude --continue` reopens "the most recent session in the current directory"; `claude --resume` opens a picker; `claude --resume <name>` resumes a named session; `claude --resume <transcript-path>` resumes the session stored in that transcript file; and `--fork-session` resumes a copy (https://code.claude.com/docs/en/sessions.md). A resumed compacted session "opens at a `Conversation compacted` row" with the last compaction's summary, the messages it left unsummarised, and every message since; summarised messages are not reloaded (https://code.claude.com/docs/en/sessions.md).

**What ends a task.** The documented model is a loop that repeats "until task complete" (https://code.claude.com/docs/en/how-claude-code-works.md). The enforcement point is the `Stop` hook, with a caveat: "`Stop` hooks fire whenever Claude finishes responding, not only at task completion. They don't fire on user interrupts" (https://code.claude.com/docs/en/hooks-guide.md). The guide's example is a completion check — a prompt hook asking the model to "Check if all tasks are complete" and answer `{"ok": false, "reason": "what remains to be done"}`, on which "Claude keeps working and uses the `reason` as its next instruction" (https://code.claude.com/docs/en/hooks-guide.md). A response may set `"impossible": true` to allow a stop the hook considers unsatisfiable (https://code.claude.com/docs/en/hooks-guide.md). The backstop: "Claude Code overrides a Stop hook after it blocks eight times in a row with no tool call from Claude in between", so hooks must check `stop_hook_active` and exit early (https://code.claude.com/docs/en/hooks-guide.md).

**License.** Proprietary. The license file reads "© Anthropic PBC. All rights reserved. Use is subject to Anthropic's [Commercial Terms of Service]" (https://github.com/anthropics/claude-code/blob/main/LICENSE.md) (repository: https://github.com/anthropics/claude-code).

## OpenClaw

**Context management.** OpenClaw's built-in compaction "summarizes the older history in one model request, whatever the size of the session or the context window", with each request's input capped at 160,000 characters, "about 40,000 tokens", or less if the summariser's window is smaller (https://docs.openclaw.ai/concepts/compaction.md). A larger history is sampled in a fixed order: "the newest messages verbatim, in half of that budget; your older messages, which carry the asks, decisions and corrections, in a quarter, each trimmed to at most 2,000 characters…; the oldest messages, in a tenth; and evenly spaced runs of the remaining messages, trimmed to 6,000 characters each" (https://docs.openclaw.ai/concepts/compaction.md). The bound "applies to the summarizer input only; the transcript keeps every message" (https://docs.openclaw.ai/concepts/compaction.md). Tool results get their own projection: 2,000 characters ordinarily, dropping to "a 500-character projection" for results older than the newest messages once a history exceeds the summary cap (https://docs.openclaw.ai/concepts/compaction.md). Auto-compaction "is on by default" and runs "when the session nears the context limit, or when the model returns a context-overflow error (in which case OpenClaw compacts and retries)"; new configs default `agents.defaults.compaction.mode` to `"safeguard"`, described as "stricter guardrails, summary quality audits" (https://docs.openclaw.ai/concepts/compaction.md).

**Persistence and resume.** Runtime session rows and transcripts default to `~/.openclaw/agents/<agentId>/agent/openclaw-agent.sqlite` (https://docs.openclaw.ai/concepts/session.md). Crash recovery is automatic: a Gateway restart resumes a persisted non-terminal run, and "there is no manual `sessions.recover` method" (https://docs.openclaw.ai/concepts/session.md). The user-facing path is `openclaw resume`, which attaches the TUI to an existing Gateway session that "stays on the Gateway"; with a query "an exact session key wins; otherwise OpenClaw requires a unique substring or fuzzy match", printing candidates and exiting 1 if ambiguous (https://docs.openclaw.ai/cli/resume.md).

**What ends a task.** OpenClaw emits lifecycle phases `start`, `finishing`, `end`, and `error` (https://docs.openclaw.ai/concepts/agent-loop.md). Completion is defined by evidence: "a confirmed final messaging-tool reply to the current source remains completion evidence across provider retries", whereas "progress-only, failed, partial, dry-run, and other-destination sends do not satisfy that requirement" (https://docs.openclaw.ai/concepts/agent-loop.md). Silence is explicit — external turns can "finish with a token-only `NO_REPLY`" — but "an empty final is not silence": it is recorded as a failed outcome (https://docs.openclaw.ai/concepts/agent-loop.md). If a required-reply turn settles its tools without composing an answer, OpenClaw "can make a tool-free finalization pass" using the settled results without repeating completed tools (https://docs.openclaw.ai/concepts/agent-loop.md). A human can always abort with a standalone `stop` or `abort` message (https://docs.openclaw.ai/help/faq/chat-commands-and-stopping.md).

**License.** MIT, per the repository's license badge (https://github.com/openclaw/openclaw) and license file (https://github.com/openclaw/openclaw/blob/main/LICENSE).

## OpenHands

**Context management.** OpenHands compresses with a *condenser* that acts on event history. The `LLMSummarizingCondenser` takes `max_size`, the "event count threshold before condensation triggers (default: 120)", and `keep_first`, the "number of initial events to preserve verbatim (default: 4)"; condensation keeps the head and tail and summarises between them, targeting `max_size // 2` events afterwards (https://docs.openhands.dev/sdk/arch/condenser.md). When the model's context window is exceeded, the runtime adds a `CondensationRequest` event to history and returns, and the request is handled on the next step through `view.unhandled_condensation_request` (https://docs.openhands.dev/sdk/arch/condenser.md).

**Persistence and resume.** With a `persistence_dir` set, each conversation gets a directory holding `base_state.json` — "the core conversation state including agent configuration, execution status, statistics, and metadata" — and an `events/` subdirectory of per-event files "named with a sequential index and event ID (e.g., `event-00000-abc123.json`)" (https://docs.openhands.dev/sdk/guides/convo-persistence.md). Resume means constructing a new `Conversation` with the same `persistence_dir` and `conversation_id` and calling `run()` (https://docs.openhands.dev/sdk/guides/convo-persistence.md).

**What ends a task.** A turn ends when the model emits text rather than a tool call: the documented step turns tool calls into `ActionEvent`s, and "Text message → `MessageEvent` and return" (https://docs.openhands.dev/sdk/arch/agent.md). A `Stop` hook fires "when the agent tries to finish", is blocking-capable, and can return `{"decision": "deny", "reason": "..."}` to prevent the finish (https://docs.openhands.dev/openhands/usage/customization/hooks.md). An independent terminator is the stuck detector, on by default, which halts execution on five patterns: the same action yielding the same observation 4+ times, the same action erroring 3+ times, monologue of 3+ consecutive messages, alternating action-observation pairs 6+ cycles, and repeated context-window errors (https://docs.openhands.dev/sdk/guides/agent-stuck-detector.md).

**License.** MIT, "Copyright © 2025 OpenHands contributors" (https://github.com/OpenHands/OpenHands/blob/main/LICENSE).

## Goose (Block)

The repository is now under the Agentic AI Foundation (AAIF) at the Linux Foundation (https://github.com/aaif-goose/goose) and its documentation is at https://goose-docs.ai (index: https://goose-docs.ai/llms.txt).

**Context management.** Goose layers auto-compaction with fallback "context strategies", the latter "used if the context limit is still exceeded after auto-compaction" (https://goose-docs.ai/docs/guides/sessions/smart-context-management.md). Auto-compaction "is triggered by default when you reach 80% of the token limit or 225,000 tokens, whichever comes first", with the effective trigger computed as `min(GOOSE_AUTO_COMPACT_THRESHOLD × model context window, GOOSE_AUTO_COMPACT_TOKEN_LIMIT)` and recalculated per model (https://goose-docs.ai/docs/guides/sessions/smart-context-management.md). `/compact` compacts on demand and `/summarize` "still works as a deprecated alias" (https://goose-docs.ai/docs/guides/sessions/smart-context-management.md). The fallback strategies are `summarize`, `truncate` ("Automatically remove oldest messages"), `clear` ("Automatically clear session") and `prompt`, selected with `GOOSE_CONTEXT_STRATEGY`; headless `goose run` "Automatically summarizes (equivalent to `summarize`)" (https://goose-docs.ai/docs/guides/sessions/smart-context-management.md).

**Persistence and resume.** "Starting with version 1.10.0, goose uses a SQLite database (`sessions.db`)" at `~/.local/share/goose/sessions/sessions.db` "instead of individual `.jsonl` files", with legacy files left on disk but "no longer managed by goose" (https://goose-docs.ai/docs/guides/sessions/session-management.md). `goose session --resume` accepts `--name`, `--session-id` or `--path` (an exported session); `--fork` "Create a new duplicate session with copied history" and requires `--resume` (https://goose-docs.ai/docs/guides/goose-cli-commands.md).

**What ends a task.** Goose defines a turn as "one complete prompt-response interaction between goose and the LLM" (https://goose-docs.ai/docs/guides/sessions/smart-context-management.md), and its documented stop condition is a budget. `Max Turns` "is the maximum number of consecutive turns that goose can take without user input (default: 1000)"; at the limit "goose stops and prompts: 'I've reached the maximum number of actions I can do without user input. Would you like me to continue?'", continuing until the limit if the user agrees (https://goose-docs.ai/docs/guides/sessions/smart-context-management.md). `--max-turns` overrides it per run (https://goose-docs.ai/docs/guides/goose-cli-commands.md), and `goose run --recipe` "executes and exits", so the end of the recipe is the end of the task (https://goose-docs.ai/docs/guides/goose-cli-commands.md). A hook that vetoes the model's own finish is not found in primary sources for Goose.

**License.** Apache-2.0 (https://github.com/aaif-goose/goose, https://github.com/aaif-goose/goose/blob/main/LICENSE).

## What they agree on, and where they differ

All five agree that the first response to a full window is to summarise older history in place. Codex compacts at a configured token threshold (https://learn.chatgpt.com/docs/config-file/config-reference.md), Claude Code "as you approach the limit" (https://code.claude.com/docs/en/how-claude-code-works.md), OpenClaw in "one model request" (https://docs.openclaw.ai/concepts/compaction.md), OpenHands by condensing events (https://docs.openhands.dev/sdk/arch/condenser.md), and Goose at 80% of the window or 225,000 tokens (https://goose-docs.ai/docs/guides/sessions/smart-context-management.md). Truncation and clearing exist everywhere but as a fallback: in Goose, `truncate` and `clear` are the documented backup strategies (https://goose-docs.ai/docs/guides/sessions/smart-context-management.md).

All five persist conversations to disk by default and provide a resume verb: `codex resume` (https://learn.chatgpt.com/docs/developer-commands.md?surface=cli), `claude --resume` (https://code.claude.com/docs/en/sessions.md), `openclaw resume` (https://docs.openclaw.ai/cli/resume.md), a rebuilt `Conversation` in OpenHands (https://docs.openhands.dev/sdk/guides/convo-persistence.md), and `goose session --resume` (https://goose-docs.ai/docs/guides/goose-cli-commands.md). The substrate differs — SQLite for OpenClaw and Goose, per-event JSON files for OpenHands — but not the capability.

Point three is where they diverge most. Codex, Claude Code and OpenHands all let a `Stop` hook veto the model's decision to finish and feed a structured reason back as the next instruction (https://learn.chatgpt.com/docs/hooks.md, https://code.claude.com/docs/en/hooks-guide.md, https://docs.openhands.dev/openhands/usage/customization/hooks.md). Codex also makes the human's goal text the completion criteria (https://learn.chatgpt.com/docs/long-running-work.md), and OpenHands adds a stuck detector that ends runs the model will not end (https://docs.openhands.dev/sdk/guides/agent-stuck-detector.md). OpenClaw defines completion by delivery evidence instead, treating an empty final as failure (https://docs.openclaw.ai/concepts/agent-loop.md), while Goose's documented stop is a turn budget of 1000 (https://goose-docs.ai/docs/guides/sessions/smart-context-management.md). Claude Code and Goose thus both carry a numeric backstop — eight consecutive blocks, or 1000 turns — the pragmatic answer to a hook or a model that never concludes.

Licenses split four to one: Apache-2.0 for Codex (https://github.com/openai/codex) and Goose (https://github.com/aaif-goose/goose), MIT for OpenClaw (https://github.com/openclaw/openclaw) and OpenHands (https://github.com/OpenHands/OpenHands/blob/main/LICENSE), proprietary Commercial Terms for Claude Code (https://github.com/anthropics/claude-code/blob/main/LICENSE.md). For anyone who needs to change compaction or resume behaviour rather than configure it, that is the deciding difference.
